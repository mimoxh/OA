# OA 手机端 M0 真机测试清单

> 配合 `docs/mobile/M0-validation-report.md` 使用。目的：在国产主力机型上确认「自建长连接 + 前台服务」的送达率，作为 M2 是否追加极光/个推的依据。
> 每款机型约需 1.5 小时（其中锁屏等待 30 分钟 × 2）。
> M2 已实现正式的后台推送（三类提醒、开机自启、断线补拉），真机验收按 `docs/mobile/M2-device-checklist.md` 做；本清单 §4 第 7 项（重启）以 M2 清单为准。

## 1. 机型

至少各一台，尽量覆盖较新的系统版本：

| 品牌 | 系统 | 机型 / 系统版本 | 测试人 | 日期 |
| --- | --- | --- | --- | --- |
| 小米 / 红米 | HyperOS（或 MIUI 14） | | | |
| 华为 / 荣耀 | HarmonyOS 4.x（Android 兼容）/ MagicOS | | | |
| OPPO / 一加 | ColorOS | | | |
| vivo / iQOO | OriginOS | | | |

> 纯血鸿蒙（HarmonyOS NEXT）不能安装 APK，不在本期范围。

## 2. 准备

1. 服务器：NAS 上的 OA，**优先用 HTTPS 地址**（局域网 HTTP 下目前发不出消息，见报告 §3.1；只测接收的话 HTTP 也可以）。
2. 两个账号：手机上登录 A，电脑浏览器登录 B（B 用来发消息）。
3. 安装 `app-debug.apk`（需允许「安装未知应用」；部分机型要先关闭「纯净模式」或「安装安全检查」）。
4. 记录：Android 版本、WebView 版本（启动页「诊断信息」里有）。

## 4. 后台送达（核心）

每项 B 发 3 条消息（间隔 10 秒），记录到达几条、首条延迟（以 B 点发送的时刻为准）。

先做「默认设置」一轮，再做「已加白名单」一轮。加白名单的方法见 §5。

| # | 场景 | 默认设置：到达 / 延迟 | 白名单后：到达 / 延迟 |
| --- | --- | --- | --- |
| 1 | App 回到桌面，屏幕亮着，1 分钟后发 | | |
| 2 | 回桌面后锁屏，5 分钟后发 | | |
| 3 | **回桌面后锁屏 30 分钟**（不充电），再发 | | |
| 4 | 从最近任务里划掉 App，1 分钟后发 | | |
| 5 | 划掉 App 后锁屏 30 分钟（不充电），再发 | | |
| 6 | Wi-Fi 切到移动数据（或反过来）后 1 分钟发（需外网可达的地址） | | |
| 7 | 重启手机，不打开 App，5 分钟后发 | （原型未做开机自启，预期收不到，记录即可） | |

## 5. 白名单设置路径（各厂商菜单名称会随版本变化，以实际为准）

启动页的「忽略电池优化」会弹出系统对话框；「应用设置」打开本应用的系统设置页。其余需要手动：

| 品牌 | 自启动 | 电池 / 后台 |
| --- | --- | --- |
| 小米 / 红米 | 设置 → 应用设置 → 应用管理 → 协作平台 OA → 自启动：开 | 同页「省电策略」→ 无限制；最近任务里下拉卡片加锁 |
| 华为 / 荣耀 | 设置 → 应用和服务 → 应用启动管理 → 协作平台 OA → 关闭「自动管理」，打开自启动、关联启动、后台活动 | 设置 → 电池 → 更多电池设置 → 休眠时始终保持网络连接 |
| OPPO / 一加 | 设置 → 应用 → 自启动管理 → 打开 | 应用详情 → 耗电管理 → 允许后台行为 / 允许完全后台行为 |
| vivo / iQOO | i 管家 → 应用管理 → 权限管理 → 自启动 → 打开 | 设置 → 电池 → 后台耗电管理 → 允许后台高耗电 |

| 机型 | 默认设置 30 分钟锁屏 | 白名单后 30 分钟锁屏 | 划掉 App 后 | 1 小时耗电 | 问题 |
| --- | --- | --- | --- | --- | --- |
| | | | | | |

判断标准（M2 验收线）：加白名单后，锁屏 30 分钟的消息在 10 秒内送达。达不到的机型占比较高时，M2 追加极光/个推。

# OA 手机端 M2 真机测试清单：后台推送

> **已合并**：真机统一按 `docs/mobile/device-checklist.md`（M0–M4 合并版，按优先级排列）测试，本文件只保留作历史记录。

> 配合 `docs/mobile/M2-report.md` 使用。M2 只在模拟器上验证过（负责人决定：真机测试放到 M4 之后统一做），本清单列出模拟器无法代替、必须在真机上确认的项目。
> 前置：`docs/mobile/M0-device-checklist.md` 的 §1 机型、§2 准备、§5 白名单路径继续适用。每款机型约需 2.5 小时（其中锁屏等待 30 分钟 × 2、耗电基线 1 小时）。

## 1. 准备

1. 服务器用 HTTPS 地址（公网 CA 证书），另测一轮局域网 HTTP。
2. 三个账号：手机登录 A；电脑浏览器登录 B（发消息）；另一台电脑或浏览器登录 A（测“电脑在用时手机静默”）。
3. 安装 M2 的 `app-debug.apk`，登录 A 后打开「我的 → 通知」，确认连接状态为「已连接，后台可接收」。
4. 记录：品牌、系统版本、Android 版本、WebView 版本、是否已忽略电池优化、是否已开自启动。

## 2. 三类提醒与点击跳转

每项先做「默认设置」，再按「我的 → 通知 → 后台保活设置引导」完成白名单后重做。延迟以 B 点发送的时刻为准，验收线 10 秒。

| # | 场景 | 预期 | 默认设置：到达 / 延迟 | 白名单后：到达 / 延迟 |
| --- | --- | --- | --- | --- |
| 1 | App 回桌面，亮屏 1 分钟后，B 发单聊 | 渠道「单聊消息」，标题为 B 的姓名 | | |
| 2 | 同上，B 在群里发普通消息 | 渠道「群聊消息」，正文「B：内容」 | | |
| 3 | 同上，B 在群里 @A | 渠道「@我」，正文以「[有人@我]」开头 | | |
| 4 | 同上，B 提交审批给 A | 渠道「审批与系统通知」，标题「审批助手」 | | |
| 5 | **锁屏 30 分钟（不充电）**后，依次做 1、3、4 | 都在 10 秒内到达 | | |
| 6 | 从最近任务划掉 App，锁屏 30 分钟后做 1 | 到达（多数国产 ROM 默认会杀后台，记录实际结果） | | |
| 7 | **重启手机，不打开 App**，解锁后 2 分钟做 1 | 开机自启后到达 | | |
| 8 | 断网（飞行模式）期间 B 发 2 条单聊 + 1 条 @A，恢复网络 | 恢复后 1 分钟内补出提醒，单聊一条通知显示 2 条，不重复 | | |
| 9 | Wi-Fi 与移动数据互切后 1 分钟做 1 | 到达 | | |
| 10 | 点 1、3、4 的通知 | 分别进入对应会话 / 审批助手会话；按返回回到消息列表 | | |

## 3. 规则（真机上抽查即可，单元测试和模拟器已覆盖）

| # | 场景 | 预期 | 结果 |
| --- | --- | --- | --- |
| 1 | A 把群设为免打扰，B 在群里发普通消息 / @A | 普通消息不提醒；@A 提醒 | |
| 2 | A 停在与 B 的会话里，B 发消息 | 不弹系统通知 | |
| 3 | A 停在消息列表，B 发消息 | 弹提醒 | |
| 4 | 电脑上 A 的 OA 页面在前台并刚操作过，B 发单聊 | 手机不提醒；电脑弹浏览器通知 | |
| 5 | 电脑上读了 / 回复了该会话 | 手机上该会话的通知自动消失 | |
| 6 | App 退到后台 1 分钟以上，B 看 A 的在线状态 | 显示离线（后台连接不算在线） | |

| 机型 | 默认 30 分钟锁屏 | 白名单后 30 分钟锁屏 | 重启不打开 | 划掉后 | 1 小时耗电 | 问题 |

| | | | | | | |

判断标准：白名单后锁屏 30 分钟、重启不打开 App 两项在 10 秒内送达。达不到的机型占比较高时，启用 `PUSH_DRIVERS=realtime,jpush`（或 getui）并补齐厂商通道（见 `M2-report.md` §7）。

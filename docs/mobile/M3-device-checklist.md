# OA 手机端 M3 真机测试清单：白板、审批、文档只读

> 配合 `docs/mobile/M3-report.md` 使用。M3 只在模拟器上验证过（负责人决定：真机测试放到 M4 之后统一做），本清单列出模拟器无法代替、必须在真机上确认的项目。
> 前置：`docs/mobile/M0-device-checklist.md` 的 §1 机型、§2 准备继续适用；推送相关项目见 `M2-device-checklist.md`。每款机型约需 1.5 小时。

## 1. 准备

1. 安装 M3 的 `app-debug.apk`（本次改了原生层：`openExternal`、相机 `<queries>`，必须用新包）。
2. 两个账号：手机登录审批人 A；电脑浏览器登录申请人 B。
3. 准备两块白板：一块普通白板（约 30 个元素）；一块**接近上限**的大白板（白板数据接近 1 MB 上限、含多张图片）。
4. 准备一份带表格、PDF 附件、TXT 附件的文档，并从电脑端「分享到会话」发给 A。
5. 记录：品牌、系统版本、Android 版本、WebView 版本、屏幕刷新率、系统导航方式（手势导航 / 三键导航）。

## 2. 白板帧率与手势

帧率可用「开发者选项 → GPU 呈现模式分析」或 `adb shell dumpsys gfxinfo com.oa.suite.mobile` 采集；至少记录目测是否卡顿。

| # | 场景 | 预期 | 普通白板 | 大白板 |
| --- | --- | --- | --- | --- |
| 1 | 查看模式单指连续平移 10 秒 | 跟手，无明显卡顿 | | |
| 2 | 双指连续缩放 10 秒（25% ↔ 300%） | 跟手，缩放中心在两指中间 | | |
| 3 | 编辑模式手指快速画笔 | 线条连续，不断笔 | | |
| 4 | 拖动元素、缩放元素 | 跟手 | | |
| 5 | 单指操作中途落下第二根手指 | 当前单指操作取消，转为缩放，不留下半截笔迹或误移动 | | |
| 6 | **手势导航**：从屏幕左 / 右边缘向内滑（系统返回手势） | 执行系统返回，不在画布上留下笔迹；或至少不丢数据（记录实际行为） | | |
| 7 | 从屏幕底部上滑（回桌面手势） | 回桌面，白板已保存的内容不丢 | | |
| 8 | 系统字体 / 显示大小调到最大 | 底部工具栏可横向滚动，按钮不重叠 | | |

## 3. 长按、软键盘、相机

| # | 场景 | 预期 | 结果 |
| --- | --- | --- | --- |
| 1 | 长按元素 | 弹出操作面板；**不出现系统选字 / 放大镜 / 振动反馈异常** | |
| 2 | 新建便签、文字，弹出软键盘（含第三方输入法：搜狗、讯飞、百度等） | 编辑框在键盘上方可见；中文输入法候选栏不遮挡编辑框 | |
| 3 | 输入中切换横屏 / 分屏 | 编辑框仍可见，不丢输入 | |
| 4 | 「上传图片 → 拍照」 | 打开系统相机，拍照确认后插入白板；不弹 CAMERA 权限请求 | |
| 5 | 「上传图片 → 从相册选择」 | 打开系统相册 / 文件选择器，选图后插入白板 | |
| 6 | 选一张超过 10 MB 的图片 | 提示「图片超过 10MB 大小限制」，白板不被破坏 | |
| 7 | 拍照过程中系统回收了 App 进程（低内存机型常见） | 回到 App 后白板仍可用，记录照片是否丢失 | |

## 4. 冲突

| # | 场景 | 预期 | 结果 |
| --- | --- | --- | --- |
| 1 | 手机与电脑同时打开同一白板，电脑先改并保存，手机再改 | 手机显示「版本冲突」横幅，电脑的修改不被覆盖 | |
| 2 | 横幅中点「复制草稿」，粘贴到便签 / 微信 | 粘贴出完整 JSON | |
| 3 | 点「载入最新版本」 | 原生确认框；确定后显示电脑端最新内容 | |
| 4 | 编辑中断网 30 秒再恢复 | 显示保存失败并可重试，恢复后保存成功，不丢修改 | |

## 5. 审批、文档

| # | 场景 | 预期 | 结果 |
| --- | --- | --- | --- |
| 1 | B 提交审批，A 手机锁屏 | 收到「审批助手」通知（见 M2 清单的延迟要求） | |
| 2 | 点通知 → 卡片「同意」 | 处理成功；B 收到结果卡片 | |
| 3 | 卡片「驳回」，用中文输入法填意见 | 对话框和「确认驳回」按钮在键盘上方可见 | |
| 4 | 详情页输入评论 | 底部操作栏让开，「发送」可见可点；收起键盘后操作栏恢复 | |
| 5 | 手机上看长表单审批（如采购单） | 底部操作栏不遮挡最后一行；全面屏手势条不遮挡按钮 | |
| 6 | 点 IM 中分享的文档 | App 内打开为只读 | |
| 7 | 下载 PDF、TXT 附件，点下载完成通知 | 用系统应用打开；记录没有 PDF 阅读器时的提示 | |
| 8 | 文档里的宽表格 | 表格内横向滚动，与页面纵向滚动不冲突 | |
| 9 | 工作台「打开 Web 完整版」 | 打开系统默认浏览器（非 Chrome 的国产浏览器也要测） | |

| 机型 | 普通白板流畅 | 大白板流畅 | 返回手势冲突 | 软键盘 | 拍照 / 相册 | 审批全流程 | 问题 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| | | | | | | | |

判断标准：普通白板在中端机上缩放、平移、画笔无明显卡顿；系统返回手势不会在画布上留下误操作或丢数据；拍照和相册两条路径都能插入图片；审批全流程在锁屏状态下可完成。大白板在低端机上卡顿时，记录元素数和机型，作为后续优化（分块绘制 / 降低缩放中的重绘频率）的依据。

# OA 手机端真机测试清单（M0–M4 合并版）

> M0–M4 都只在模拟器上验证过（负责人决定：真机测试在 M4 之后统一做）。本清单合并了 `M0-device-checklist.md`、`M2-device-checklist.md`、`M3-device-checklist.md` 并补充 M4（正式签名、下载页、升级），按优先级排列：**P0 每台必测，P1 每台测、时间不够时可抽查，P2 至少一台测**。各期报告里的背景和模拟器结果见 `M0-validation-report.md`、`M1-report.md` … `M4-report.md`。
>
> 一台手机全部做完约 4 小时（其中锁屏等待 30 分钟 × 3、耗电基线 1 小时）。只做 P0 约 1.5 小时。

纯血鸿蒙（HarmonyOS NEXT）不能安装 APK，不在范围内。WebView 版本在启动页「诊断信息」里可以看到。

### 环境

1. 服务器：NAS 上的 OA，**用 HTTPS 地址**（公共 CA 证书，见 `deployment.md`）；P1 另测一轮局域网 HTTP。
2. 发布目录里先发布一个**旧版本**（例如构建 `0.0.9` 测试包，方法见 `BUILD.md` §6），升级测试时再发布正式版本。
3. 账号：手机登录 A（审批人）；电脑浏览器登录 B（申请人，用来发消息、提交审批）；另一个浏览器登录 A（测「电脑在用时手机静默」）；换账号测试用 C。
4. 测试数据：一块普通白板（约 30 个元素）和一块接近 1 MB 上限的大白板；一份带表格、PDF、TXT 附件的文档；PDF 测试文件（3 页小文件、约 20 MB / 100 页大文件、加密文件、损坏文件，见 `.tmp/m3b-mkpdf.mjs`）。
5. 手机上如果装过 debug 包，先卸载（debug 包与正式包签名不同，不能覆盖）。

推送延迟一律以 B 点发送的时刻为准，验收线 **10 秒**。各项先在默认设置下测，再按「我的 → 通知 → 后台保活设置引导」完成白名单后重测（白名单路径见 §6）。

| # | 场景 | 预期 | 结果 |

| 1 | 电脑打开 `/download/android`，用手机相机或浏览器扫码 | 手机打开下载页，显示版本号、大小、更新说明 | |
| 2 | 点「下载安装包」，按浏览器提示「保留」；下载完点「打开」 | 系统提示未知来源 → 去设置允许 → 返回安装成功；记录各品牌额外拦截（纯净模式、安全检测）和处理方式 | |
| 3 | 打开 App，填服务器地址 → 连接 → 登录 A | 进入消息页；允许通知后出现「后台连接」常驻通知 | |
| 4 | 「我的」页 | 版本号正确；「检查更新」提示「已是最新版本」 | |
| 5 | 改一项通知设置（如把「群聊消息」类别设为静音），记下当前服务器地址 | — | |
| 6 | 管理员发布新版本（不加 `--min`），从最近任务划掉 App 再打开 | 约 2 秒后弹出「发现新版本」，显示更新说明 | |
| 7 | 点「立即更新」 | 显示下载进度；首次会出现「允许安装更新」引导 → 去设置打开 → 返回 App 自动弹出系统「更新」对话框 | |
| 8 | 点「更新」→「打开」 | 版本号变为新版本；**仍是登录状态**；服务器地址、第 5 步的通知设置、后台接收开关都保留 | |
| 9 | 升级后 B 发私信，A 锁屏 | 收到通知（升级后后台服务自动恢复） | |
| 10 | 再发布一个版本，加 `--min latest`；重新打开 App | 弹出「需要更新到 x.y.z」，**返回键和点空白处都关不掉**，只有「立即更新」和「切换服务器」；完成更新后可正常使用 | |
| 11 | 有新版本时点「稍后」，再划掉重开 | 24 小时内同一版本不再自动提示；「我的 → 检查更新」仍会提示 | |
| 12 | 下载更新过程中切到后台 1 分钟再回来 | 进度继续，下载完自动进入安装 | |
| 13 | 下载过程中断网 | 提示下载暂停 / 失败，可「重试」或「在浏览器下载」 | |

## 2. P0 后台推送（M0 / M2）

| # | 场景 | 预期 | 默认设置：到达 / 延迟 | 白名单后：到达 / 延迟 |
| --- | --- | --- | --- | --- |
| 1 | App 回桌面，亮屏 1 分钟后 B 发单聊 | 渠道「单聊消息」，标题为 B 的姓名 | | |
| 2 | 同上，B 在群里发普通消息 | 渠道「群聊消息」，正文「B：内容」 | | |
| 3 | 同上，B 在群里 @A | 渠道「@我」，正文以「[有人@我]」开头 | | |
| 4 | 同上，B 提交审批给 A | 渠道「审批与系统通知」，标题「审批助手」 | | |
| 5 | **锁屏 30 分钟（不充电）**后依次做 1、3、4 | 都在 10 秒内到达 | | |
| 6 | **重启手机，不打开 App**，解锁后 2 分钟做 1 | 开机自启后到达 | | |
| 7 | 点 1、3、4 的通知 | 分别进入对应会话 / 审批助手会话；返回回到消息列表 | | |
| 8 | 断网（飞行模式）期间 B 发 2 条单聊 + 1 条 @A，恢复网络 | 1 分钟内补出提醒，单聊一条通知显示 2 条，不重复 | | |

判断标准：白名单后「锁屏 30 分钟」「重启不打开」两项在 10 秒内送达。达不到的机型占比较高时，启用 `PUSH_DRIVERS=realtime,jpush`（或 getui）并补齐厂商通道（`M2-report.md` §7）。

## 6. 白名单设置路径（菜单名称随系统版本变化，以实际为准）

「我的 → 通知」的「忽略电池优化」会弹出系统对话框，其余需要手动：

| 品牌 | 自启动 | 电池 / 后台 |
| --- | --- | --- |
| 小米 / 红米 | 设置 → 应用设置 → 应用管理 → 协作平台 OA → 自启动：开 | 同页「省电策略」→ 无限制；最近任务里下拉卡片加锁 |
| 华为 / 荣耀 | 设置 → 应用和服务 → 应用启动管理 → 协作平台 OA → 关闭「自动管理」，打开自启动、关联启动、后台活动 | 设置 → 电池 → 更多电池设置 → 休眠时始终保持网络连接 |
| OPPO / 一加 | 设置 → 应用 → 自启动管理 → 打开 | 应用详情 → 耗电管理 → 允许后台行为 / 允许完全后台行为 |
| vivo / iQOO | i 管家 → 应用管理 → 权限管理 → 自启动 → 打开 | 设置 → 电池 → 后台耗电管理 → 允许后台高耗电 |

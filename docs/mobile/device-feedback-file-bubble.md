# 真机反馈：聊天里的文件消息框盖住右侧头像（小米）

> 分支 `mimoxh/oa-mobile-research`。反馈原文：「当前我发送了一个 pdf 文件，文件消息框将右侧的头像框给遮住了」。
>
> 验证环境：Android 模拟器 `oa_mi_api37`（Android 17，1220×2712），手势导航和三键导航；视口宽度用 `wm density` 切换（440 → CSS 443px，542 → CSS 360px），系统字体用 `font_scale` 切换（1.0 / 1.3）。桌面 1440×900 用无头 Edge 做前后像素对比。截图在 `docs/mobile/fb4-screenshots/`。
>
> 纯 Web 改动，App 不用重新安装，服务端更新后刷新页面或重新进入聊天即可生效。改动全部是 `max-md:`（< 768px）的样式，桌面不变。

## 结论

| 项目 | 修复前 | 修复后 |
| --- | --- | --- |
| 自己发的文件（360px） | 文件框 55.4–325.5，头像列 312.2–344.2，**盖住头像 13.3px** | 文件框 55.4–304.2，头像列 312.2–344.2，间隔 8px |
| 收到的文件（360px） | 文件框 56–326.1，超出气泡列 21.5px（向右，没有头像所以看不出来） | 文件框 56–304.8，不超出 |
| 审批卡片（360px） | 卡片 56–344.1，超出气泡列 39.5px | 卡片 56–304.8，不超出 |
| 443px（模拟器默认宽度） | 没有遮挡（间隔 8px） | 不变（文件框仍是 280px） |
| 头像 | 32×32 | 32×32 |
| 页面横向滚动 | 无（`scrollWidth` = `innerWidth`） | 无 |
| 桌面 1440×900 | — | 与修复前一致（像素对比见下文） |

## 根因

手机上一条消息的结构是：

```
行（px-4）
└─ 消息块（flex gap-2，最多占行宽 88%）
   ├─ 头像列 w-8 shrink-0（32px）
   └─ 气泡列 min-w-0（可以收窄）
      └─ 气泡（w-fit，手机上 max-w-full）
         └─ 文件框 w-[280px] max-w-[75vw]
```

文件框的宽度上限是按**视口**算的（`75vw`），而它能用的空间是**气泡列**的宽度：`0.88 × (视口宽 − 32) − 40`（40 = 头像 32 + 间距 8）。视口窄的时候，前者比后者大：

| 视口宽度 | 文件框宽度 | 气泡列宽度 | 文件框超出气泡列 |
| --- | --- | --- | --- |
| 443（模拟器默认） | 280 | 321.7 | 不超出 |
| 393 | 280 | 277.7 | 2.3（进入间距） |
| 386.5 | 280 | 272 | 8（刚好碰到头像） |
| 360 | 270 | 248.7 | 21.4（盖住头像 13.4） |

气泡列有 `min-w-0`，会正常收窄；气泡也有 `max-w-full`，会跟着收窄；但文件框自己是固定宽度，不跟着收窄，于是溢出气泡。自己发的消息靠右（`flex-row-reverse` + `items-end`），溢出的部分向右伸进头像列，盖住头像的左边。收到的消息靠左，溢出的部分向右伸进空白区，所以看不出来。

**结论：CSS 视口宽度小于约 387px 时，自己发的文件框一定会盖住头像。** 模拟器默认 443px，所以之前几轮看不出来。小米手机上调大「显示大小」或者使用较高的显示密度时，CSS 宽度常在 360–393px，这就是真机上出现的原因。系统字体大小不影响这个问题：文件框和气泡列都是 px 宽度，字体 1.3 时测得的横向边界和字体 1.0 完全一样（见下方测量）。

审批 / 任务等业务卡片（`card-view.tsx`）是同样的写法（`w-[320px] max-w-[80vw]`），360px 下超出气泡列 39.5px。目前卡片都是机器人或系统发的（在左侧），所以没有盖住头像，但如果以后有自己发的卡片，会出现同样的问题。

已检查无需修改：

- 引用预览卡片（`ref-preview.tsx`，分享的文档 / 白板等）：已经是 `max-w-full`，不超出。
- 图片消息：手机上限宽 `60vw`，在 243px 以上的视口都小于气泡列，不超出。
- 引用回复条（气泡顶部的「李娜：[文件] …」）：`w-full`，跟着气泡宽度折行。
- 头像：头像列 `w-8 shrink-0`，`Avatar` 组件本身也是 `shrink-0`，所有情况下都是 32×32。

## 修改

| 文件 | 改动 |
| --- | --- |
| `src/components/im/message-item.tsx` | 文件消息框加 `max-md:max-w-full`：手机上以气泡宽度为上限，不再按视口宽度 |
| `src/components/im/card-view.tsx` | 业务卡片加 `max-md:max-w-full`，同上 |
| `tests/mobile/message-bubble-width.test.ts` | 新增结构断言：头像列 `w-8 shrink-0`、气泡列 `min-w-0`、消息块 88%、气泡 `max-md:max-w-full`、文件框和卡片 `max-md:max-w-full`、文件名单行截断、右侧图标 `shrink-0`、引用卡片 `max-w-full` |

文件框缩窄后，内部是 `flex`：左边的文件图标（`size-10 shrink-0`）和右边的预览 / 下载图标（`size-4 shrink-0`）宽度不变，中间的文件名（`min-w-0 flex-1` + `truncate`）缩短并显示省略号。

## 测量

测量脚本是 `.tmp/fb4/measure.mjs`：通过 WebView 调试端口，对聊天页每一条消息取「气泡列里所有可见元素的最左 / 最右边界」和「头像列边界」。自己发的消息看「内容右边缘 < 头像列左边缘」，收到的消息看「内容左边缘 > 头像列右边缘」；同时检查头像是否 32×32、内容是否超出屏幕、页面 `scrollWidth` 是否等于 `innerWidth`。从聊天底部往上逐屏截图，每屏一份 JSON。

测试数据：在 B → A 单聊（李娜）里新增了这些消息（原有的 5 个文件和 3 张文档分享卡片保留）：

- A 发的 PDF：`合同.pdf`、`2026年第四季度华东区域销售合同审批材料汇总（含附件与补充说明）最终版.pdf`、`Q4-2026-East-China-Regional-Sales-Contract-Approval-Package-final-v3.pdf`；
- B 发的长文件名 PDF（中文、英文各一个），B 引用 A 的文件回复文字，B 引用 A 的文件再发一个文件；
- A 引用 B 的文件再发一个文件（自己发的、带引用的文件），A 引用文件回复文字，A 发文档链接（自己发的引用卡片）。

审批卡片用「审批助手」会话里已有的 5 张待审批卡片。

## 遗留

- 宽屏下，自己发的带引用的文件消息，文件框靠气泡左边，右边和引用条之间留空（443px 下文件框 65.4–345.4，引用条到 387.6）。这是修复前就有的排版，不会遮挡，本次没有改。
- 模拟器上装的是 0.1.0 debug 包（调试版才能连 WebView 调试端口做测量），不是手机上的 0.1.4。这次是纯页面样式问题，两个版本加载的是同一套页面，结果一致。
- 无法确认负责人手机的 CSS 视口宽度。按上面的计算，只要小于约 387px 就会出现这个问题；修复后任何宽度下文件框都不会超出气泡。

## 小米真机复测

1. 打开 App（不用更新），进入和任意同事的单聊，下拉刷新一次。
2. 发一个 PDF，最好是长文件名，例如 `2026年第四季度华东区域销售合同审批材料汇总（含附件与补充说明）最终版.pdf`。
3. 看自己发的文件框：右边和自己的头像之间留有一条小缝，头像是完整的圆，文件名太长时末尾显示「…」，右侧的预览图标完整显示。
4. 点文件框，PDF 预览正常打开。
5. 让同事发一个长文件名的 PDF，看收到的文件框：在左侧头像的右边，不超出屏幕。
6. 长按一个文件消息 → 回复，发一个文件，看带引用的文件消息也不盖住头像。
7. 打开「审批助手」，审批卡片完整显示，「同意 / 驳回」按钮能点。
8. 在 设置 → 显示 里调大「显示大小」和「字体大小」各一档，重复第 3、5、7 步。
9. 整个聊天页左右拖动时不会横向滚动。

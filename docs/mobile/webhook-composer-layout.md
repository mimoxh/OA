# 真机反馈：Webhook 机器人聊天输入框排版（基座 / 模型 / 思考强度移到输入框上方）

> 分支 `mimoxh/oa-webhook-composer-bar`（从 `master` 922f94e 新建）。反馈原文：「webhook连接的orca输入框的排版不好看，可以将基座，模型选择和思考强度放在消息框的上面而不是现在一样放在输入框的里面」。
>
> 验证环境：Android 模拟器 `oa_mi_api37`（emulator-5554，1220×2712），手势导航和三键导航；视口宽度用 `wm density` 切换（440 → CSS 443px，542 → CSS 360px）。桌面 1440×900 用无头 Edge。测试服务是本工作区的 `next dev`（端口 3460，独立的 `prisma/dev.db`，用 `adb reverse` 给模拟器），跑完已把 App 切回原来的服务地址、密度和导航方式。截图在 `docs/mobile/fb6-screenshots/`。
>
> 纯 Web 改动，App 不用重新安装。

## 结论

| 项目 | 修复前 | 修复后 |
| --- | --- | --- |
| 配置条位置 | 在圆角输入框里面，和表情 / 图片 / 附件、「发送」挤在一起折行 | 圆角输入框正上方，单独一行 |
| 圆角输入框高度（360px） | 144.1px（4 行：文字、图标、配置、发送） | 80.1px（文字 + 图标和「发送」同一行），和真人聊天一样 |
| 圆角输入框高度（443px） | 111.8px（3 行） | 79.8px |
| 整个输入区高度（360px / 443px） | 161 / 128.6px | 131 / 130.6px |
| 工具图标与「发送」 | 不在同一行 | 同一行（中心线差 < 2px） |
| 弹层位置（360px） | 贴着屏幕左边（left = 0） | 离屏幕边缘至少 8px，从配置条向上展开、左对齐 |
| 页面横向滚动 | 无 | 无（`scrollWidth` = `innerWidth`：443 / 361 / 1440） |
| 真人聊天 | — | 与修复前像素一致 |
| 桌面 1440×900 | 配置在输入框工具栏右侧 | 同样放在输入框上方；输入区高 148.3px（原 114.3px），圆角框本身不变（74.8px） |

## 修改

| 文件 | 改动 |
| --- | --- |
| `src/components/im/composer.tsx` | `toolbar` 改为 `topBar`：渲染在回复提示和圆角输入框之前；放不下时横向滚动、隐藏滚动条（`min-w-0 overflow-x-auto`），不撑宽页面。输入框内的工具行去掉 `flex-wrap`，左边是表情 / 图片 / 附件，右边是「发送」 |
| `src/components/im/chat-view.tsx` | 单聊和群聊都通过 `topBar` 传入 `WebhookRunConfigBar`（同一个挂载点，两种场景位置和样式一致）。没有 Webhook 机器人的会话不传，不渲染任何容器 |
| `src/components/im/webhook-run-config-bar.tsx` | 三个弹层改为 `side="top" align="start"`，`collisionPadding` 四周 8px，顶部再加状态栏高度（手机布局下 body 的 `padding-top` 就是 `--sat`）；弹层最大高度取 Radix 计算的可用高度，最大宽度 `100vw - 16px`，放不下时内部滚动。胶囊只压缩模型 ID（`shrink`），基座限宽 128px 不压缩，强度不压缩 |
| `tests/mobile/webhook-composer-layout.test.ts` | 新增 6 个结构断言：配置条在圆角框之前、不进工具栏；横向滚动容器；工具行不折行；真人 / 话题不渲染；胶囊压缩规则；三个弹层的方向、对齐、避让和尺寸限制 |

为什么是「只压缩模型 ID」：360px 下配置条可用宽度 345px。默认状态（Codex / 默认模型 / 默认强度）一共约 280px，放得下。会话已切换且模型 ID 很长时（例如 `claude-opus-5-5-20261101-extended-context-preview`），原来模型和基座按权重一起压缩，「Claude」会被截成「Cla…」。现在只压缩模型 ID（截断后 149px，显示省略号），「Claude」保持完整。模型压到最小宽度（44px）时，整条最多约 277px，360px 下不会出现横向滚动；更窄的屏幕会在配置条内部横向滚动。

## 遗留

- 模拟器上的 WebView 没有进入 edge-to-edge（`--sat` / `--sab` 都是 0），所以「弹层避让状态栏」只验证了 `--sat` = 0 的情况；`--sat` > 0 时顶部间距会自动加上状态栏高度（读取 body 的 `padding-top`），这部分逻辑没有在真机上看到。
- 桌面上配置条单独占一行，输入区比原来高 34px，消息列表相应少 34px。
- 没有更新测试实例 3400 / NAS 镜像；合入后需要重新部署才会在手机上生效。

## 小米真机复测

1. 打开 App（不用更新），进入和 Mimo 的单聊，下拉刷新一次。
2. 看输入区：基座（Codex）、模型、思考强度在圆角输入框的上方一行；输入框里只有文字，下面一行左边是表情 / 图片 / 附件，右边是「发送」。
3. 依次点基座、模型、思考强度：弹层从配置条往上展开，左右离屏幕边缘都有空隙，顶部不被状态栏挡住；选一项后弹层关闭，胶囊变成蓝色，右边出现重置按钮。
4. 模型弹层里点搜索框弹出输入法，弹层仍然完整显示在输入法上方。
5. 进入有 Mimo 的群聊，配置条的位置和样式与单聊一样；`@Mimo` 发一条消息正常。
6. 进入和同事的单聊，输入框和以前一样，没有多出的空白。
7. 整个聊天页左右拖动时不会横向滚动。
